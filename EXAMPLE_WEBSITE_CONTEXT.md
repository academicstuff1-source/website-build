# Example Website Context

## Purpose

Build a simple fictional one-page marketing website for practice.
This is not a real client project.

## Fictional Business

Name: Lumen Desk

Lumen Desk is a fictional administrative-support service for solo
wellness professionals. It helps them organize inquiries, reminders,
follow-up, and routine administrative tasks.

Do not make claims about real clients, results, HIPAA compliance,
security, certifications, testimonials, revenue, or performance.

## Target Visitor

Solo wellness professionals and small studio owners who are busy,
client-facing, and tired of repetitive admin work.

## Primary CTA

"Book a Free Workflow Call"

For this demo, the CTA should link to `#contact`.

## Required Sections

Build only these sections, in this order:

1. Sticky header
   - Lumen Desk logo text
   - Links: Services, How It Works, About
   - Primary CTA button

2. Hero
   - Eyebrow: "Administrative support for independent wellness businesses"
   - Headline: "More time with clients. Less time chasing admin."
   - Supporting copy about inquiries, reminders, follow-up, and organization
   - Primary CTA: "Book a Free Workflow Call"
   - Secondary CTA: "See How It Works"
   - Calm abstract visual, desk image, or placeholder illustration

3. Benefits
   - Heading: "A clearer day starts with a clearer workflow."
   - Three benefits:
     - Respond to new inquiries more consistently
     - Keep appointment reminders organized
     - Reduce repetitive follow-up tasks

4. How It Works
   - Heading: "Simple support, shaped around your routine."
   - Steps:
     - Share your current workflow
     - Choose the areas that need support
     - Use a clearer, more consistent process

5. Closing CTA
   - Heading: "Make space for the work only you can do."
   - CTA: "Book a Free Workflow Call"

6. Footer
   - hello@lumendesk.example
   - Simple navigation links
   - Copyright notice

Do not add testimonials, pricing, customer logos, FAQs, blog content,
pop-ups, dashboards, feature tables, or extra sections.

## Visual Direction

The site should feel calm, warm, premium, organized, human, and modern.

Use:
- Warm off-white or cream background
- Deep charcoal text
- Muted sage-green accent
- Soft clay or warm-sand secondary accent
- Editorial serif/display type for headings
- Clean sans-serif font for body text
- Generous, intentional spacing
- Mobile-first responsive layout
- Soft borders and restrained depth
- Subtle visual treatment rather than a generic software dashboard

Avoid:
- Default Tailwind blue or indigo
- Neon gradients
- Generic AI-SaaS styling
- Heavy glassmorphism
- Excessive rounded cards
- Fake analytics dashboards
- Strongly clinical or medical visual language
- Real-looking proof, metrics, testimonials, or compliance claims

## Technical Expectations

- Use semantic HTML.
- Keep the implementation simple and maintainable.
- Use the existing project stack; if none exists, use a single `index.html`.
- Do not install dependencies unless needed.
- Run and inspect the site on localhost, never via `file:///`.
- Test responsive behavior at mobile, tablet, and desktop widths.
- Check for horizontal overflow, broken assets, unreadable text, keyboard-focus visibility, and browser-console errors.

## Agent Instructions

- Follow `.agents/rules/frontend-standards.md`.
- Use `/build-frontend` before beginning substantial frontend work.
- Do not claim the site is complete until it has been inspected in a localhost browser session.
